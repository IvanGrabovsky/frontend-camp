01 Складність

Структура HTML-документа

<!DOCTYPE> <html> <head> <body> lang

Що це таке?

HTML (HyperText Markup Language) — це мова розмітки, якою описується структура і зміст веб-сторінки. Браузер читає HTML і відображає його у вигляді, зрозумілому людині: заголовки, параграфи, посилання, зображення тощо.

Кожен HTML-документ має обов'язкову базову структуру. Відхилення від неї не завжди призводить до помилки (браузери дуже толерантні), але це погана практика, яка може спричинити непередбачувану поведінку.

🏠 Аналогія з будівництвом

HTML-документ схожий на будинок: DOCTYPE — це дозвіл на будівництво (паспорт документа). <html> — сам будинок. <head> — комунікації всередині стін (невидимі зовні, але важливі). <body> — все, що всередині і видно мешканцям.

Мінімальна правильна структура

<!-- Мінімальний валідний HTML-документ -->
<!DOCTYPE html>
<html lang="uk">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>Моя перша сторінка</title>
  </head>
  <body>
    <h1>Привіт, світ!</h1>
    <p>Це мій перший HTML-документ.</p>
  </body>
</html>

Кожна частина — детально

<!DOCTYPE html>

Не є тегом — це декларація, яка повідомляє браузеру: «цей документ написаний за стандартом HTML5». Завжди перший рядок файлу, без відступів і пробілів перед ним.

  • Без DOCTYPE браузер переходить у Quirks mode — режим зворотної сумісності зі старими сторінками 90-х. Поведінка CSS може відрізнятися.
  • В HTML5 DOCTYPE максимально короткий — раніше він містив довгі URL на DTD-специфікацію.

<html lang="uk">

Кореневий елемент — обгортає весь документ. Атрибут lang обов'язковий:

  • Скрін-рідери (для незрячих) використовують його для вибору мови синтезу мовлення.
  • Пошукові системи враховують при індексуванні.
  • CSS-властивість quotes та деякі шрифтові правила залежать від мови.
<!-- Коди мов (BCP 47) -->
<html lang="uk">    <!-- українська -->
<html lang="en">    <!-- англійська -->
<html lang="en-US"> <!-- американська англійська -->
<html lang="pl">    <!-- польська -->

<head> — невидима голова

<body> — весь видимий контент

Все, що користувач бачить і з чим взаємодіє: текст, зображення, кнопки, форми, посилання. В одному документі лише один <body>.

Як браузер обробляє HTML

  1. Завантажує HTML-файл побайтово через HTTP.
  2. Декодує байти в символи (згідно з charset з <meta charset> або HTTP-заголовка).
  3. Токенізує символи: розбиває на теги, атрибути, текст.
  4. Будує DOM-дерево (Document Object Model) — ієрархічну структуру вузлів.
  5. Рендерить дерево на екрані, застосовуючи CSS.
// DOM-дерево для нашого прикладу
Document
└─ html[lang="uk"]
   ├─ head
   │  ├─ meta[charset="UTF-8"]
   │  ├─ meta[name="viewport"]
   │  └─ title "Моя перша сторінка"
   └─ body
      ├─ h1 "Привіт, світ!"
      └─ p "Це мій перший HTML-документ."

Офіційна документація

  • html — MDN
  • head — MDN
  • DOCTYPE — HTML Living Standard
  • W3C Validator — перевірка валідності HTML
⚠️ Типові помилки
  • Забути DOCTYPE — браузер падає в Quirks mode, і поведінка CSS (особливо box model) може несподівано відрізнятися від стандарту.
  • Забути charset — символи поза ASCII (кирилиця, емодзі) відображатимуться «кракозябрами».
  • Відсутній viewport — мобільна версія матиме масштаб «10 кроків до кнопки», яку не можна натиснути.
  • Забути атрибут lang — скрін-рідери читатимуть текст неправильною мовою, що погіршує доступність.
  • Два <body> — HTML такого не дозволяє. Другий тег браузер просто ігнорує.
  • Вміст за межами <html> — технічно браузери терплять, але валідатор помилиться і поведінка непередбачувана.
⚡ Практика

Відкрий будь-який текстовий редактор (VS Code) і виконай завдання. Зберігай файл з розширенням .html і відкривай у браузері.

  1. Створи мінімальний валідний HTML-файл з DOCTYPE, lang="uk", charset, viewport і title. В <body> додай <h1> зі своїм ім'ям.
  2. Навмисно видали <!DOCTYPE html>, збережи та відкрий у браузері. Чи щось змінилось? Потім відкрий DevTools → вкладка Console: чи є попередження?
  3. Зміни lang="uk" на lang="en". Відкрий DevTools → Elements → знайди тег <html>. Побачиш атрибут. Скрін-рідер тепер читав би сторінку по-англійськи.
  4. Перевір свій файл на W3C Validator (вставки у поле Direct Input). Виправ всі помилки якщо є.
  5. Відкрий DevTools → вкладка Elements. Знайди в дереві <html> → <head> → <body>. Переконайся, що структура відповідає тому, що ти написав.

📋 Типові помилки на співбесідах

Питання: «Що таке DOCTYPE і навіщо він?»

❌ «Це просто перший рядок в HTML» — правильно, але нерозкрито навіщо.

✅ DOCTYPE повідомляє браузеру використовувати стандартний режим рендерингу (Standards mode) замість Quirks mode. Без нього CSS поводиться по-іншому — наприклад, інакша box model.

Питання: «Що йде в head, а що в body?»

❌ «У head — мета-теги» — неповно.

✅ У <head> — мета-інформація: charset, viewport, title, CSS, fonts, open graph, canonical. У <body> — весь видимий контент: текст, зображення, форми, скрипти що взаємодіють з DOM.

Питання: «Навіщо meta viewport?»

❌ «Для мобільних» — занадто розмито.

✅ Без viewport мобільний браузер симулює ширину 980px і зменшує сторінку, щоб вмістити весь «десктоп». width=device-width каже: «використовуй реальну ширину пристрою». initial-scale=1 — не масштабуй при завантаженні.

✨ Цікаві фішки
  • В VS Code введи ! і натисни Tab — автоматично вставиться мінімальна структура HTML (Emmet скорочення).
  • Браузери дуже прощають помилки: навіть без <html>, <head> і <body> сторінка відобразиться. Але DevTools покаже, що браузер сам додав ці теги в DOM.
  • <meta charset> має бути в перших 1024 байтах файлу — інакше браузер починає читати документ без знання кодування.
  • Атрибут lang можна ставити не лише на <html>, а й на окремі елементи: <span lang="en">Hello</span> — корисно для багатомовних сторінок.
  • Chrome DevTools → Lighthouse → вкладка Accessibility — автоматично перевіряє чи є lang і багато інших вимог доступності.
