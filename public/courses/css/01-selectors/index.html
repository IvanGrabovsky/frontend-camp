01 Складність

Селектори та специфічність

.class #id [attr] :pseudo :is() specificity

Що це таке?

Селектор — це шаблон, яким CSS «вибирає» HTML-елементи для застосування стилів. Вміти писати правильні селектори — ключова навичка: від них залежить як точно і без побічних ефектів ти можеш стилізувати елементи.

Специфічність — це система підрахунку «ваги» кожного правила. Коли два правила намагаються задати один і той самий стиль одному елементу, виграє той, у кого вища специфічність. Розуміння цього механізму позбавляє від хаотичних !important.

🎯 Аналогія зі знижками

Уяви, що кожне CSS-правило — це знижкова картка. Специфічність — це рівень карти: золота бʼє срібну, срібна — бронзову. Якщо у двох карток однаковий рівень, перемагає та, що пізніша в файлі (каскад). А !important — це VIP-картка, яка бʼє всіх.

Типи селекторів

/* 1. Тег (елемент) — специфічність: 0-0-1 */
p { color: gray; }
h1 { font-size: 2rem; }

/* 2. Клас — специфічність: 0-1-0 */
.btn { padding: 8px 16px; }
.card:hover { box-shadow: 0 4px 12px rgba(0,0,0,.1); }

/* 3. ID — специфічність: 1-0-0 */
#header { position: sticky; top: 0; }

/* 4. Атрибут — специфічність: 0-1-0 */
input[type="text"] { border: 1px solid #ccc; }
a[href^="https"] { color: green; }

/* 5. Псевдоклас — специфічність: 0-1-0 */
a:hover { text-decoration: underline; }
li:first-child { font-weight: bold; }
p:not(.special) { color: #333; }

/* 6. Псевдоелемент — специфічність: 0-0-1 */
p::first-line { font-variant: small-caps; }
.btn::after { content: " →"; }

/* 7. Комбінатори (не збільшують специфічність самі) */
.nav > li { display: inline-block; }    /* прямий нащадок */
.card + .card { margin-top: 1rem; }    /* суміжний брат */
.section ~ p { color: #666; }          /* всі наступні брати */

Специфічність — система підрахунку

Специфічність записується як три числа (A, B, C), де більше A завжди бʼє більше B, незалежно від C:

/* Приклади підрахунку специфічності */
p              { color: gray }      /* 0-0-1 */
.text          { color: blue }      /* 0-1-0 — перемагає */
#main p        { color: green }     /* 1-0-1 */
.nav .link     { color: purple }    /* 0-2-0 */
#main .link    { color: orange }    /* 1-1-0 — перемагає над попереднім */

/* :is() та :not() беруть специфічність найважчого аргументу */
:is(#id, .class) { color: red }     /* 1-0-0 (через #id) */
:is(p, .class)   { color: red }     /* 0-1-0 (через .class) */

Сучасні інструменти: :is(), :where(), :not()

/* :is() — скорочення для груп селекторів */
/* Замість: header a, main a, footer a */
:is(header, main, footer) a { color: blue; }

/* :where() — те саме, але специфічність завжди 0-0-0 */
/* Зручно для скидань стилів, які легко перезаписати */
:where(h1, h2, h3) { margin-top: 0; }

/* :not() — виключення */
.list li:not(:last-child) { border-bottom: 1px solid #eee; }

/* :has() — батько, що містить певний нащадок (CSS 2023) */
.card:has(img) { padding: 0; }          /* картка із зображенням */
form:has(input:invalid) { border: red; } /* форма з помилкою */

Каскад — порядок вирішення конфліктів

Коли специфічність однакова, браузер застосовує правило, що йде пізніше в CSS (каскад). Але є й інші фактори, які враховуються в такому порядку пріоритету:

  1. !important від користувача (accessibility overrides у браузері)
  2. !important від автора (ваш CSS)
  3. Стилі автора (звичайні правила у вашому CSS)
  4. Стилі браузера за замовчуванням (user-agent stylesheet)

Всередині кожного рівня: вища специфічність → пізніше у файлі → виграє.

⚠️ Типові помилки
  • Зловживання #id в CSS — специфічність 1-0-0 дуже важко перебити без ще одного ID або !important. Для стилізації краще завжди використовувати класи.
  • !important як рішення конфліктів — це симптом, а не ліки. Веде до ще більших конфліктів. Правильне рішення — зрозуміти специфічність і переписати селектор.
  • Занадто «довгі» селектори — .sidebar .nav ul li a.active важко перебити і важко читати. Краще дати елементу власний клас.
  • Плутанина :nth-child() і :nth-of-type() — :nth-child(2) вибирає другого нащадка батька (будь-якого типу). :nth-of-type(2) — другий елемент цього типу.
  • Не знати, що :is() бере специфічність найважчого аргументу — :is(#id, p) має специфічність 1-0-0, навіть якщо застосовується до p.
⚡ Практика

Відкрий онлайн-пісочницю CodePen або VS Code і виконай:

  1. Є кнопка <button class="btn" id="submit">. Напиши три правила: для тегу button, для класу .btn і для ID #submit — кожне зі своїм кольором. Яке з них перемагає? Зміни порядок правил у CSS — результат той самий?
  2. Напиши правило p { color: blue; } і .text { color: red; }. Додай елемент <p class="text">. Якого кольору текст? Тепер додай !important до правила для p — що змінилось?
  3. Перепиши header a, main a, footer a { ... } з використанням :is().
  4. Напиши правило, що стилізує всі <li> крім останнього (підказка: :not(:last-child)). Додай роздільну лінію між пунктами списку.
  5. Порахуй специфічність вручну для: div.wrapper > p:first-child::before. Відповідь перевір на specificity.keegan.st.

📋 Типові помилки на співбесідах

Питання: «Що таке специфічність CSS?»

❌ «ID важливіший за клас» — правильно, але без пояснення механізму.

✅ Специфічність — це три числа (A, B, C): A — кількість ID, B — класів/псевдокласів/атрибутів, C — тегів/псевдоелементів. При конфлікті порівнюються зліва направо. Inline-стиль ще вищий: (1,0,0,0).

Питання: «Навіщо !important і коли його використовувати?»

❌ «Коли стиль не застосовується» — неправильно, це обходить проблему, а не вирішує.

✅ !important законно для: (1) accessibility overrides — щоб стиль браузера/розширення не ламав доступність, (2) utility-класи в design systems (Tailwind теж так робить). В звичайному CSS — сигнал про проблему з архітектурою.

Питання: «Що новенького в CSS-селекторах?»

❌ Мовчання або «нічого не знаю».

✅ :is() і :where() для групування (різна специфічність), :has() — «батьківський» селектор (CSS 2023, підтримується у всіх сучасних браузерах), CSS Nesting (нативний, без препроцесорів).

✨ Цікаві фішки
  • В DevTools (Chrome) → вкладка Elements → правая панель Styles: кожне CSS-правило показує його специфічність при наведенні на селектор (Chrome 121+).
  • CSS Nesting (нативне, без SCSS) вже у всіх браузерах: .card { & .title { color: red; } } — не потрібен препроцесор.
  • :where() з нульовою специфічністю ідеальний для reset-стилів — будь-який клас їх легко перезаписує.
  • Атрибутний селектор [href$=".pdf"] вибирає посилання що закінчуються на «.pdf». ^= — починаються з, *= — містять.
  • :focus-visible замість :focus — показує outline тільки при навігації клавіатурою, але не при кліку мишею. Кращий UX + accessibility.
