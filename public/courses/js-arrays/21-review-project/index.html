Це як фінальний іспит на практиці: ти вже знаєш усі інструменти — тепер збираєш їх у один робочий механізм, як справжній frontend-розробник будує інтерфейс на чистому JavaScript.

Функціонал проекту

  • Додати студента (push)
  • Видалити студента (filter)
  • Знайти за імʼям (find)
  • Відсортувати за середнім балом (sort + reduce)
  • Відфільтрувати по групі (filter)
  • Показати статистику (reduce, every, some)
  • Експорт у CSV (map + join)

    Ніби ревʼю після здачі домашки: що часто плутають і як виправити. Як рахуються кристали →

    Завдання 1 — пошук за імʼям і групою

    ❌ Логіка OR: знаходить по імені або по групі — потрібно AND (обидві умови).

    ✅ students.filter(s => s.name.includes(q) && s.group === selectedGroup) — обидва критерії true.

    Завдання 2 — undo / стек

    ❌ Зберігають лише останній стан без можливості відкотити кілька кроків або мутують той самий масив у історії.

    ✅ Перед зміною history.push(JSON.parse(JSON.stringify(students))); undo — pop + відновити з копії.

    Завдання 3 (★) — localStorage

    ❌ Зберігають обʼєкт напряму (setItem('s', students)) — в storage лишиться [object Object].

    ✅ localStorage.setItem('students', JSON.stringify(students)) і при load — JSON.parse з перевіркою на null.

    ✨ Цікаві фішки
    • Student Manager — це збірка filter, find, map, spread — повернись до уроків, якщо застряг на одному методі.
    • Для сортування без мутації в проекті можна замінити [...students].sort(...) на students.toSorted(...).
    • У catch перевіряй помилки через Error.isError(err), а масиви — через Array.isArray(data).
    • Для undo достатньо масиву «знімків» стану; deep copy через JSON підходить для простих обʼєктів без функцій.
    • localStorage має ліміт ~5MB — для списку студентів це більш ніж достатньо.
