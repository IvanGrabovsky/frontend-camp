      <h2>Що це таке?</h2>
      <p>У <strong>Next.js App Router</strong> отримання даних (Data Fetching) здійснюється безпосередньо всередині асинхронних <strong>Server Components</strong> за допомогою нативного `fetch()` або прямих запитів до бази даних (ORM/SQL) без використання `useEffect`, `useState` чи сторонніх бібліотек.</p>
      <p>Next.js розширює стандартний Web `fetch()` власними механізмами <strong>кешування</strong>, <strong>ревалідації (ISR)</strong> та <strong>мемоізації запитів (Request Deduplication)</strong>.</p>
    </article>

      <p><strong>Static Fetch (SSG)</strong> — надруковані рекламні буклети, заготовлені на складі під час збірки (0 мс затримки, віддаються з CDN). <strong>ISR (Revalidate)</strong> — свіжі свіжоспечені круасани з таймером (склад оновлює партію кожні 60 секунд). <strong>Dynamic Fetch (SSR)</strong> — персоналізована страва на замовлення гостя в реальному часі (готується на кожен клік).</p>

      <h2>Стратегії отримання даних у fetch()</h2>
      

```text
// 1. Статичне кешування (за замовчуванням у Next.js / SSG)
const res1 = await fetch('https://api.example.com/posts');

// 2. Часова ревалідація (ISR) — оновлювати кеш не частіше ніж раз на 1 годину (3600с)
const res2 = await fetch('https://api.example.com/products', {
  next: { revalidate: 3600 }
});

// 3. Динамічний запит без кешу (SSR) — завжди свіжі дані на кожен запит користувача
const res3 = await fetch('https://api.example.com/live-stock', {
  cache: 'no-store'
});

// 4. Тегована ревалідація на вимогу (On-demand Revalidation)
const res4 = await fetch('https://api.example.com/articles', {
  next: { tags: ['articles-list'] }
});
```



      <h2>Паралельний Data Fetching vs Waterfall</h2>
      <p>Коли ви викликаєте кілька `await` послідовно, другий запит чекає завершення першого (Waterfall). Завжди використовуйте `Promise.all()` для паралельних незалежних запитів:</p>

      

```javascript
// ❌ Погано: Waterfall (час = 500ms + 500ms = 1000ms)
const user = await getUser(userId);
const posts = await getPosts(userId);

// ✅ Добре: Паралельно (час = max(500ms, 500ms) = 500ms)
const [user, posts] = await Promise.all([
  getUser(userId),
  getPosts(userId)
]);
```



      <h2>Потоковий рендеринг (Streaming) зі Suspense</h2>
      <p>Замість того, щоб змушувати користувача чекати повільного бекенду перед показом сторінки, обгорніть повільний компонент у `<Suspense>`:</p>

      

```javascript
import { Suspense } from 'react';
import { FastHeader } from './FastHeader';
import { SlowComments } from './SlowComments'; // запит триває 2 секунди

export default function PostPage() {
  return (
    <main>
      <FastHeader /> <!-- Рендериться миттєво -->
      <Suspense fallback={<p>Завантаження коментарів...</p>}>
        <SlowComments /> <!-- Підвантажується потоково без блокування шапки -->
      </Suspense>
    </main>
  );
}
```



      <h2>Оновлення даних через Server Actions</h2>
      

```javascript
// app/actions.ts — Server Action для мутацій
'use server';

import { revalidateTag, revalidatePath } from 'next/cache';

export async function createPost(formData: FormData) {
  const title = formData.get('title');
  await db.post.create({ data: { title } });

  // Миттєво інвалідує кеш сторінки блогу
  revalidateTag('articles-list');
  revalidatePath('/blog');
}
```

    <section className="tip-block tip-block--warn">
      <div className="tip-block__title"><span>⚠️</span> Типові помилки</div>
      <ul>
        <li><strong>Використання `useEffect` + `fetch()` для первинного завантаження</strong> — призводить до "порожнього білого екрана", погіршує SEO та збільшує розмір клієнтського JS. У Next.js App Router завантажуйте дані на сервері в async Server Components.</li>
        <li><strong>Створення штучного Waterfall</strong> — послідовні виклики `await getA(); await getB();`, які не залежать один від одного. Завжди об'єднуйте їх у `Promise.all()`.</li>
        <li><strong>Забута ревалідація після мутації</strong> — якщо після додавання товару не викликати `revalidatePath()` чи `revalidateTag()`, користувач продовжить бачити закешований старий список.</li>
        <li><strong>Дублювання однакових fetch-запитів</strong> — у Next.js запити з однаковим URL автоматично мемоізуються (Request Deduplication), тому не бійтеся викликати `fetchUser()` у Layout і в Page одночасно.</li>
