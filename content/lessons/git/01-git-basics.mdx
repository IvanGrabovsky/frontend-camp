<article className="lesson-card">
  <h2>Що таке Git і чому він незамінний?</h2>
  <p>
    <strong>Git</strong> — це розподілена система контролю версій (DVCS), створена Лінусом Торвальдсом у 2005 році. Вона дозволяє зберігати повну історію змін кожного файлу у вашому проекті, легко перемикатися між версіями, експериментувати у безпечних гілках та ефективно працювати в команді.
  </p>
</article>

<section className="analogy-block">
  <div className="analogy-block__title"><span className="analogy-block__icon">📸</span> Git — як машина часу з точками збереження у грі</div>
  <p>
    Уяви проходження складної компʼютерної гри: перед боєм із босом ти робиш <strong>Save Point (комміт)</strong>. Якщо щось піде не так — ти завжди можеш завантажити збереження і спробувати іншу стратегію (гілку). При цьому гра зберігає не всю гру заново, а лише різницю між станами.
  </p>
</section>

<section>
  <h2>Три стани файлів у Git</h2>
  <p>Кожен файл у проекті під керуванням Git проходить через 3 основні зони:</p>

  <ul>
    <li><strong>Working Directory (Робоча директорія):</strong> файли на вашому диску, які ви редагуєте в IDE.</li>
    <li><strong>Staging Area / Index (Індекс / Зона підготовки):</strong> файли, підготовлені командою <code>git add</code> для наступного збереження.</li>
    <li><strong>Git Repository (.git / Історія):</strong> база даних знімків (коммітів), збережених назавжди командою <code>git commit</code>.</li>
  </ul>

```bash
# 1. Ініціалізація нового репозиторію
git init

# 2. Перевірка статусу файлів
git status

# 3. Додавання файлів до Staging Area
git add index.html style.css
# або додати всі змінені файли:
git add .

# 4. Створення знімка (комміту) зі змістовним повідомленням
git commit -m "feat: add hero section and navigation bar"
```

  <h2>Корисні команди для щоденної роботи</h2>

```bash
# Перегляд історії коммітів
git log --oneline --graph --decorate

# Перегляд різниці між робочою директорією та останнім коммітом
git diff

# Перегляд змін лише у staged файлах
git diff --staged
```

  <h2>Найкращі практики повідомлень коммітів (Conventional Commits)</h2>
  <p>Пишіть комміти зрозумілою англійською або українською мовою з префіксами типу змін:</p>
  <ul>
    <li><code>feat:</code> — нова функціональність для користувача</li>
    <li><code>fix:</code> — виправлення багу</li>
    <li><code>refactor:</code> — рефакторинг коду без зміни поведінки</li>
    <li><code>docs:</code> — оновлення документації</li>
    <li><code>style:</code> — форматування, відступи (без зміни логіки)</li>
  </ul>
</section>
