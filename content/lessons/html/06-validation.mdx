      <h2>Стилізація стану полів через CSS псевдокласи</h2>
      

```html
/* 1. Поле обов'язкове до заповнення */
input:required {
  border-left: 3px solid #6366f1;
}

/* 2. Сучасний псевдоклас :user-invalid (підсвічує помилку ТІЛЬКИ після спроби взаємодії!) */
input:user-invalid {
  border-color: #ef4444;
  background-color: #fef2f2;
}

/* 3. Успішно заповнене валідне поле після вводу */
input:user-valid {
  border-color: #10b981;
}
```



      <h2>JavaScript Constraint Validation API</h2>
      <p>Браузер надає властивості та методи об'єкта `HTMLInputElement` для програмного контролю валідації:</p>

      

```html
const input = document.querySelector('#username');

// 1. Перевірка валідності (повертає true / false)
if (!input.checkValidity()) {
  console.log('Поле не пройшло перевірку!');
}

// 2. Об'єкт validity — деталі причини помилки
console.log(input.validity.valueMissing);   // true якщо пусте required поле
console.log(input.validity.typeMismatch);   // true якщо не email/url
console.log(input.validity.patternMismatch);// true якщо не збігається з pattern
console.log(input.validity.tooShort);       // true якщо менше minlength

// 3. Встановлення кастомного повідомлення рідною мовою
input.setCustomValidity('Будь ласка, введіть коректне імʼя українською мовою');
input.reportValidity(); // показує спливаючу підказку браузера
```

    <section className="tip-block tip-block--warn">
      <div className="tip-block__title"><span>⚠️</span> Типові помилки</div>
      <ul>
        <li><strong>Довіра клієнтській валідації</strong> — будь-яку HTML-валідацію можна обійти за 1 секунду в DevTools або через cURL! Клієнтська валідація потрібна для UX, а серверна валідація — єдиний захист безпеки.</li>
        <li><strong>Використання `:invalid` замість `:user-invalid`</strong> — псевдоклас `:invalid` спрацьовує одразу при завантаженні сторінки, через що порожні поля світяться червоним ще до того, як користувач встиг доторкнутися до клавіатури.</li>
        <li><strong>Забуте скидання `setCustomValidity('')`</strong> — якщо встановити кастомну помилку, поле буде вважатися невалідним <strong>назавжди</strong>, поки ви явно не викличете `input.setCustomValidity('')` з порожнім рядком.</li>
        <li><strong>Складний `pattern` без атрибута `title`</strong> — якщо користувач введе невірний формат за регулярним виразом, браузер покаже підказку саме з тексту атрибута `title`. Без нього користувач не зрозуміє, що саме пішло не так.</li>
      </ul>

        <li>Подія `invalid` на інпуті спрацьовує, коли форма не проходить валідацію. Можна викликати `e.preventDefault()`, щоб замінити стандартну бульбашку браузера на гарний кастомний тост чи повідомлення.</li>
