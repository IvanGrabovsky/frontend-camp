# 02. Основи алгоритмів та логічне мислення розробника

<article className="lesson-card">
  <h2>Що таке алгоритм?</h2>
  <p><strong>Алгоритм</strong> — це точна, однозначна і скінченна послідовність кроків (інструкцій), виконання яких приводить від початкових даних до вирішення поставленого завдання або досягнення конкретної мети.</p>
  <p>Уся розробка програмного забезпечення, від простої кнопки на сайті до складних нейромереж, зводиться до розбиття складних проблем на ланцюжок зрозумілих комп'ютеру алгоритмічних кроків.</p>
</article>

<section className="analogy-block">
  <div className="analogy-block__title"><span className="analogy-block__icon">☕</span> Аналогія: Кулінарний рецепт або збірка меблів IKEA</div>
  <p>
    Кулінарний рецепт приготування борщу чи інструкція збірки шафи з IKEA — це типові алгоритми:
  </p>
  <ul>
    <li><strong>Вхідні дані (Input)</strong>: інгредієнти (буряк, м'ясо, картопля) або деталі з гвинтами.</li>
    <li><strong>Покроковий процес (Process)</strong>: 1. Почистити овочі; 2. Зварити бульйон; 3. Додати засмажку.</li>
    <li><strong>Вихідний результат (Output)</strong>: готова смачна страва або надійно зібрана шафа.</li>
  </ul>
  <p>Якщо порушити послідовність (наприклад, спробувати з'їсти суп до того, як запалити вогонь), результат буде зіпсовано.</p>
</section>

<section>
  <h2>Ключові властивості будь-якого алгоритму</h2>
  <ol className="space-y-2">
    <li><strong>Дискретність</strong>: процес розбитий на окремі, чітко розмежовані елементарні кроки.</li>
    <li><strong>Визначеність (детермінованість)</strong>: кожна команда має бути абсолютно однозначною і не допускати двоякого трактування.</li>
    <li><strong>Результативність</strong>: після виконання скінченної кількості дій алгоритм обов'язково повинен завершитися і надати результат (або повідомити про помилку).</li>
    <li><strong>Масовість</strong>: алгоритм має вирішувати не одну конкретну задачу з одними числами, а цілий клас однотипних задач із різними вхідними даними.</li>
  </ol>

  <h2>3 базові алгоритмічні конструкції</h2>
  <p>Будь-яка програма в світі побудована з комбінації лише трьох фундаментальних блоків:</p>

  <div className="grid grid-cols-1 md:grid-cols-3 gap-4 my-6">
    <div className="p-4 rounded-xl border border-border bg-card">
      <h3 className="text-primary font-bold mb-2">1. Лінійний (послідовний)</h3>
      <p className="text-xs text-muted-foreground leading-relaxed">
        Усі команди виконуються строго по черзі одна за одною від початку до кінця без пропусків та поворотів.
      </p>
    </div>
    <div className="p-4 rounded-xl border border-border bg-card">
      <h3 className="text-primary font-bold mb-2">2. Розгалужений (умовний)</h3>
      <p className="text-xs text-muted-foreground leading-relaxed">
        Залежно від перевірки умови (істина чи хиба) вибирається один із кількох можливих шляхів подальших дій.
      </p>
    </div>
    <div className="p-4 rounded-xl border border-border bg-card">
      <h3 className="text-primary font-bold mb-2">3. Циклічний (повторюваний)</h3>
      <p className="text-xs text-muted-foreground leading-relaxed">
        Певна група команд повторюється багаторазово, поки виконується задана умова (наприклад, перебір списку товарів).
      </p>
    </div>
  </div>

  <h2>Способи запису алгоритму: Псевдокод та Блок-схеми</h2>
  <p>
    Перш ніж писати код мовою JavaScript, досвідчені програмісти формулюють рішення <strong>псевдокодом</strong> (мовою, схожою на людську) або візуалізують блок-схемою.
  </p>

```text
// Псевдокод: Алгоритм покупки товару в інтернет-магазині
АЛГОРИТМ КупитиТовар(Товар, БалансКлієнта):
  1. Отримати ціну Товару
  2. ЯКЩО БалансКлієнта >= ЦінаТовару ТОДІ:
       Зняти ЦінуТовару з Балансу
       Сформувати чек
       Надіслати товар у службу доставки
       ПОВЕРНУТИ "Успішна покупка"
     ІНАКШЕ:
       Вивести "Недостатньо коштів на балансі"
       ПОВЕРНУТИ "Відмова"
КІНЕЦЬ АЛГОРИТМУ
```

  <h2>Трасування (Dry Run): ручна перевірка логіки</h2>
  <p>
    <strong>Трасування</strong> — це метод перевірки правильності алгоритму на папері або в голові, коли ви покроково фіксуєте значення змінних для тестових вхідних даних (наприклад, <code>Баланс = 500</code>, <code>Ціна = 350</code>).
  </p>
</section>

<section className="interactive-demo mb-12">
  <h2>🧪 Інтерактивна демонстрація: Лінійний алгоритм розрахунку замовлення</h2>
  <p className="text-muted-foreground text-sm mb-4">
    Подивіться, як комп'ютер крок за кроком виконує інструкції, обчислює проміжні результати та формує фінальний звіт.
  </p>
  <CodeRunner
    title="Алгоритм розрахунку доставки піци"
    initialCode={`// 1. Вхідні дані (Input)
const pizzaPrice = 250;     // ціна однієї піци (грн)
const quantity = 3;         // кількість
const deliveryFee = 60;     // доставка (грн)
const discountThreshold = 600; // поріг для безкоштовної доставки

console.log("Крок 1: Отримано замовлення на " + quantity + " піци.");

// 2. Обробка (Processing)
const subtotal = pizzaPrice * quantity;
console.log("Крок 2: Вартість без доставки: " + subtotal + " грн.");

// 3. Умовна логіка
const finalDelivery = subtotal >= discountThreshold ? 0 : deliveryFee;
console.log("Крок 3: Вартість доставки: " + finalDelivery + " грн.");

// 4. Фінальний результат (Output)
const total = subtotal + finalDelivery;
console.log("--------------------------------");
console.log("🎉 РАЗОМ ДО СПЛАТИ: " + total + " грн.");`}
  />
</section>

<section className="tip-block tip-block--warn">
  <div className="tip-block__title"><span>⚠️</span> Типові помилки алгоритмічного мислення</div>
  <ul>
    <li><strong>Пропуск граничних випадків (Edge Cases)</strong>: що станеться, якщо кількість піц дорівнює 0, або баланс клієнта від'ємний? Хороший алгоритм завжди враховує некоректні вхідні дані.</li>
    <li><strong>Нескінченні цикли</strong>: якщо умова виходу з циклу ніколи не стає хибною, програма зависає і споживає 100% ресурсів процесора.</li>
    <li><strong>Порушення порядку ініціалізації</strong>: спроба використати результат розрахунку до того, як він був обчислений попередніми рядками.</li>
  </ul>
</section>
